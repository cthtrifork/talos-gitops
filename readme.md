# talos-gitops

GitOps configuration for a Talos Linux homelab Kubernetes cluster, managed with Flux Operator, Cilium and SOPS/age.

## Bootstrap

Install Cilium before enabling Flux. This cluster uses Cilium in place of Flannel and kube-proxy. The chart version is the tag pinned in `k8s/infra/cilium/helm-repository.yaml`.

```sh
helm install cilium oci://quay.io/cilium/charts/cilium \
  --version 1.20.5 \
  --namespace kube-system \
  --set ipam.mode=kubernetes \
  --set kubeProxyReplacement=true \
  --set securityContext.capabilities.ciliumAgent="{CHOWN,KILL,NET_ADMIN,NET_RAW,IPC_LOCK,SYS_ADMIN,SYS_RESOURCE,DAC_OVERRIDE,FOWNER,SETGID,SETUID}" \
  --set securityContext.capabilities.cleanCiliumState="{NET_ADMIN,SYS_ADMIN,SYS_RESOURCE}" \
  --set cgroup.autoMount.enabled=false \
  --set cgroup.hostRoot=/sys/fs/cgroup \
  --set k8sServiceHost=localhost \
  --set k8sServicePort=7445 \
  --set routingMode=native \
  --set autoDirectNodeRoutes=true \
  --set enableIPv4Masquerade=true \
  --set ipMasqAgent.enabled=false \
  --set ipv4NativeRoutingCIDR=10.244.0.0/16 \
  --kubeconfig ./kubeconfig.yaml

kubectl --kubeconfig ./kubeconfig.yaml -n kube-system delete daemonset kube-proxy kube-flannel
kubectl --kubeconfig ./kubeconfig.yaml -n kube-system delete configmap kube-flannel-cfg

# Talos does not render CoreDNS (patches/23-coredns.yaml, applied in Omni first) and Flux needs DNS to fetch Git: install it from
# the values of its HelmRelease; the release has the same name, so Flux then adopts it (docs/coredns.md)
helm install coredns oci://ghcr.io/coredns/charts/coredns \
  --version "$(yq '.spec.ref.tag' k8s/infra/coredns/helm-repository.yaml)" \
  --namespace kube-system \
  --values <(yq '.spec.values' k8s/infra/coredns/helm-release.yaml) \
  --kubeconfig ./kubeconfig.yaml

kubectl --kubeconfig ./kubeconfig.yaml apply -f \
  https://github.com/controlplaneio-fluxcd/flux-operator/releases/latest/download/install.yaml

kubectl --kubeconfig ./kubeconfig.yaml -n flux-system create secret generic sops-age \
  --from-file=age.agekey="$HOME/sops/age/keys.txt"

kubectl --kubeconfig ./kubeconfig.yaml apply -f k8s/clusters/homelab/flux-instance.yaml
```

## Secrets (SOPS)

Kubernetes Secrets are stored in Git as SOPS-encrypted `*.enc.yaml` files. Encryption uses the age public key configured in `.sops.yaml`; Flux decrypts with `flux-system/sops-age`. The SOPS key itself must be backed up securely outside Git.

To edit an existing encrypted Secret:

```sh
export SOPS_AGE_KEY_FILE="$HOME/sops/age/keys.txt"
sops edit k8s/apps/claude-system/claude-github-app.enc.yaml
```

To import an existing Secret from the cluster into Git, replace the namespace, Secret name and destination path:

```sh
set -o pipefail
kubectl -n claude-system get secret claude-github-app -o json \
  | jq '{apiVersion: "v1", kind: "Secret", metadata: {name: .metadata.name, namespace: .metadata.namespace}, type: .type, data: .data}' \
  | sops encrypt --filename-override k8s/apps/claude-system/claude-github-app.enc.yaml \
      --input-type json --output-type yaml /dev/stdin \
  > claude-github-app.enc.yaml.tmp \
  && mv claude-github-app.enc.yaml.tmp k8s/apps/claude-system/claude-github-app.enc.yaml
```

Include new Secret files under `resources:` in the directory's `kustomization.yaml`, then commit. Flux reconciles the encrypted manifests. Only workloads configured for Reloader or other Secret-change handling are restarted automatically.

Secrets such as cert-manager-generated certificates remain operator managed. Do not recreate or rotate the Dependency-Track KEK without an application-specific re-key procedure.

### Secrets generated in the cluster (External Secrets)

Random secrets that must not be in Git (the Garage keys, the Dependency-Track KEK and admin password, the fileserver upload token) are generated by
External Secrets (`k8s/infra/controllers/external-secrets/`) into a cluster store: the namespace `secret-store`, exposed as the
`ClusterSecretStore` `secret-store` (Kubernetes provider, `k8s/infra/secret-store/`). A Password generator and a PushSecret write each value
once (`updatePolicy: IfNotExists`, only the fileserver token is replaced every 30 days), and an ExternalSecret in the namespace that
needs it copies it into a normal Secret. To add one: a generator in `password.yaml` and a PushSecret in `pushsecret.yaml`, an ExternalSecret next
to the workload, and the workload's namespace in the `conditions` of the ClusterSecretStore. To read one: `kubectl -n secret-store get secret <name>`
(needs Secret read access). To regenerate one, delete the key in `secret-store`; the copies follow within the refresh interval.

Anyone who can create an ExternalSecret in a namespace listed in the store's `conditions` can read every Secret in `secret-store`.

Check encrypted Secret policy with:

```sh
bash scripts/ci/check-secrets-encrypted.sh
```

## Maintenance

- Rotate credentials with `sops edit` and update the corresponding external service as needed.
- To rotate the age key, update `.sops.yaml`, re-encrypt all SOPS files and update `flux-system/sops-age` before removing the old key.
- Use `kubectl --kubeconfig ./kubeconfig.yaml` and `talosctl --talosconfig ./talosconfig.yaml` for cluster diagnostics.
